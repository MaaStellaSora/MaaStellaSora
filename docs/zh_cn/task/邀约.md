# 邀约任务维护说明

本文记录邀约任务的 Pipeline、Agent 实现关系及维护注意事项。Custom 函数的通用约定见 [Custom 函数编写规范](../custom函数编写规范.md)，Pipeline 的节点与覆盖规则见 [Pipeline 编写规范](../Pipeline编写规范.md)。

## 模块职责

- `assets/interface/tasks/invite.json` 声明邀约任务、选项及其 Pipeline 覆盖。
- `assets/resource/{base,tw,en,jp,kr}/pipeline/invite/invite.json` 声明公共流程与区服覆盖。
- `agent/custom/action/invite.py` 注册 `InviteAuto`，负责邀约对象识别、匹配、自动查找和邀约流程衔接。
- `tools/checks/tests/test_invite.py` 覆盖邀约对象匹配及 OCR 结果整理逻辑。

## 区服识别与 OCR 清理

`InviteAuto.run` 从「邀约_总循环」节点的 `attach.lang` 读取当前区服并保存为实例状态，供识别、合并和匹配逻辑使用。基础资源设为 `cn`；台服、国际服、日服、韩服分别在对应资源覆盖中设为 `tw`、`en`、`jp`、`kr`。新增或修改区服时，需同步检查该节点覆盖及其资源叠加结果。

邀约列表 OCR 清理集中在 `_get_refined_merge` 合并前的过滤阶段：

- 低置信度、以 `P` 开头且不符合标题大小写形式的结果，以及单字符结果，作为通用噪声过滤。
- 国际服保留英文识别结果；其他区服过滤独立 ASCII 文本碎片。
- 韩服按韩文客户端处理，过滤不含韩文的 OCR 项；不额外兼容非韩文界面配置。

清理后再按位置合并同一张旅人卡片的文本。不要把区服噪声清理分散到合并循环或合并结果之后；新增过滤条件时，在此处按通用规则或对应区服条件组织，并为各相关区服补充回归测试。

韩服的旅人名匹配使用 `_similarity` 中的韩文包含关系检查和 자모 相似度，匹配阈值也按 `lang == "kr"` 选择。其他区服沿用普通字符串相似度，不根据 OCR 文本内容推断区服。

## 验证

修改邀约 Agent 或 OCR 清理逻辑时，运行：

```powershell
python -m unittest tools.checks.tests.test_invite
```

修改 Pipeline 区服覆盖时，按 [资源加载顺序](../项目结构.md#资源加载)验证受影响区服的资源组合；公共邀约节点修改还需检查五个区服及 Windows 叠加。
