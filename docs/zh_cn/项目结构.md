# 项目结构

本文介绍项目的源码目录、资源加载方式、开发工具和发行包布局。

节点表达与覆盖写法见 [Pipeline 编写规范](Pipeline编写规范.md)。

## 目录与入口

```text
MaaStellaSora/
├── AGENTS.md                # AI 工具的项目阅读与开发入口
├── .github/                 # PR 审计说明、Issue 模板与工作流
├── agent/                   # Python 自定义动作与识别
├── assets/
│   ├── interface.json       # 项目入口
│   ├── interface/tasks/     # 界面任务、选项及预设
│   ├── resource/            # base、tw、en、jp、windows 资源包
│   ├── requirements.txt     # 运行依赖
│   ├── CONTACT              # 发行包联系方式
│   └── MaaCommonAssets/     # 上游公共资源子模块
├── docs/
│   ├── CONTRIBUTING.md      # 贡献方式、调试与 PR 提交说明
│   └── zh_cn/               # 中文工程、使用与配置文档
├── tools/
│   ├── checks/              # 资源加载检查、提交检查配置及依赖
│   ├── ci/                  # 准备、打包及测试
│   └── format/              # Prettier 配置、npm 依赖与锁文件
├── deps/tools/              # 上游 JSON Schema
└── page/                    # 项目展示页面
```

| 路径 | 职责 |
| --- | --- |
| `docs/CONTRIBUTING.md` | 贡献方式、调试截图与日志、PR 提交说明，供 README 和 GitHub 贡献入口引用 |
| `assets/interface.json` | 开发环境的项目入口，声明控制器、资源、Agent 和任务导入顺序 |
| `assets/interface/tasks/` | 界面任务、选项及预设声明，通过 `interface.json` 的 `import` 加载 |
| `assets/resource/{base,tw,en,jp,windows}/` | MaaFramework 资源包，包含 Pipeline、图片及所需模型 |
| `assets/requirements.txt`、`assets/CONTACT` | 随发行包提供的运行依赖清单与联系方式 |
| `agent/` | Python 自定义识别与动作 |
| `tools/checks/check_resource.py` | 按参数顺序加载资源包，检查框架能否正常解析 |
| `tools/checks/requirements.txt` | 资源检查使用的 Python 依赖 |
| `tools/checks/pre-commit-config.yaml` | 图片、JSON/YAML 和 Markdown 的提交检查配置 |
| `tools/ci/` | 依赖准备、版本解析和发行打包；测试仍在此目录 |
| `tools/format/` | `.prettierrc`、npm 格式化依赖、锁文件及本地安装的 `node_modules/` |
| `deps/tools/` | 项目已有的 JSON Schema |
| `assets/MaaCommonAssets/` | 上游公共资源子模块，供打包阶段准备 OCR 模型 |
| `docs/`、`page/` | 项目文档与展示页面 |

根目录的 `README.md`、`LICENSE` 分别提供项目说明和许可证，`AGENTS.md` 提供 AI 工具的开发指引，`.gitignore`、`.gitmodules` 分别定义 Git 忽略规则和子模块。贡献指南位于 `docs/CONTRIBUTING.md`，检查与格式化配置随对应工具放在 `tools/` 下。

各资源包采用上游约定的 `pipeline/`、`image/`、`model/` 层级。Pipeline 内按功能分组；语言与平台资源包包含各自的覆盖文件。

| Pipeline 分组 | 内容 |
| --- | --- |
| `common/` | `base.json` 和公共战斗、事件、记录选择节点 |
| `daily/` | 登录、好友、基金、邮件、委托、商店、交流、任务领奖 |
| `combat/` | 作战、猎影合围、真格挑战 |
| `activity/` | 活动及活动挑战 |
| `invite/` | 邀约 |
| `climb_tower/` | 爬塔 Pipeline |

框架递归加载 `pipeline/` 中的 JSON，同一资源包的 Pipeline 文件共享节点命名空间。图片路径相对于资源包的 `image/` 目录。

## 源码与发行布局

MFAAvalonia 与 MXU 分别通过 `tools/ci/install.py`、`tools/ci/install_mxu.py` 打包，并共用 `tools/ci/resource_layout.py` 的资源路径映射。

当前 CI 构建与发行使用 MFAAvalonia，覆盖 Windows、Linux 和 macOS 的 x64、ARM64 平台。MXU 打包入口保留供本地使用。

构建使用上游最新的非草稿发布版本，包含预发布版。MaaFramework 的 Python 绑定优先使用同版本、对应平台的 PyPI wheel；缺失时，`tools/ci/prepare_maafw.py` 使用宿主 Python 从同一标签的源码与 SDK 构建 wheel，供发行 Python 安装。

`tools/ci/package_common.py` 提供发行文件复制、构建缓存过滤和必要文件校验。两个打包入口各自转换客户端界面声明，MFA 根据目标平台设置 Python 启动路径。OCR 模型由 `tools/ci/configure.py` 在发行资源目录中准备：使用完整的既有模型，缺失时从公共资源导入默认模型，并校验检测模型、识别模型及字符表。

| 源码路径 | 发行包路径 |
| --- | --- |
| `assets/interface.json` | `interface.json`，保留各客户端已有的发行转换 |
| `assets/interface/tasks/` | `interface/tasks/` |
| `assets/requirements.txt` | `requirements.txt` |
| `assets/CONTACT` | `CONTACT` |
| `assets/resource/<包>/pipeline/common/base.json` | `resource/<包>/pipeline/base.json` |
| `assets/resource/<包>/pipeline/{daily,combat,activity,invite}/<文件>.json` | `resource/<包>/pipeline/<文件>.json` |
| `assets/resource/<包>/pipeline/common/` 中其他文件 | `resource/<包>/pipeline/common/` |
| `assets/resource/<包>/pipeline/climb_tower/` | `resource/<包>/pipeline/climb_tower/` |
| `assets/resource/<包>/{image,model}/` | `resource/<包>/{image,model}/` |

打包器根据路径映射，将源码中的功能分组转换为表中列出的发行目录。

界面入口通过 `import` 加载 `interface/tasks/` 中的任务声明。开发环境的 Agent 入口为相对于 `assets/interface.json` 所在目录的 `../agent/main.py`，发行包中的入口为 `agent/main.py`。

## 资源加载

官服加载 `base` 资源包；台服、国际服、日服分别在 `base` 之后加载 `tw`、`en`、`jp`。桌面控制器通过 `attach_resource_path` 最后追加 `windows`，安卓和 PlayCover 使用所选区服的资源包。

资源按声明顺序叠加，后加载资源覆盖先加载资源。界面入口按 `import` 顺序导入任务和选项：任务依次追加，同名选项由后导入的定义覆盖。
