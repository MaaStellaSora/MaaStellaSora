# 项目结构

本文介绍项目的源码目录、资源加载方式、开发工具和发行包布局。

节点表达与覆盖写法见 [Pipeline 编写规范](Pipeline编写规范.md)。

## 目录与入口

```text
MaaStellaSora/
├── AGENTS.md                # AI 工具的项目阅读与开发入口
├── .github/                 # PR 审计说明、Issue 模板与工作流
├── agent/                   # Python 自定义动作与识别
├── assets/
│   ├── interface.json       # 项目入口
│   ├── interface/tasks/     # 界面任务、选项及预设
│   ├── i18n/                # 界面翻译文件
│   ├── resource/            # base、tw、en、jp、kr、windows 资源包
│   ├── models/              # 公共资源以外的 OCR 模型及说明
│   ├── requirements.txt     # 运行依赖
│   ├── CONTACT              # 发行包联系方式
│   └── MaaCommonAssets/     # 上游公共资源子模块
├── docs/
│   ├── CONTRIBUTING.md      # 贡献方式、调试与 PR 提交说明
│   └── zh_cn/               # 中文工程、使用与配置文档
├── tools/
│   ├── checks/              # 资源加载检查、提交检查配置及依赖
│   ├── ci/                  # MFAAvalonia、MXU 打包及测试
│   ├── i18n/                # 繁体中文翻译生成工具及依赖
│   └── format/              # Prettier 配置、npm 依赖与锁文件
├── deps/tools/              # 上游 JSON Schema
├── vendor/MaaFwApp/         # MaaFwApp 子模块（Android 构建）
└── page/                    # 项目展示页面
```

| 路径 | 职责 |
| --- | --- |
| `docs/CONTRIBUTING.md` | 贡献方式、调试截图与日志、PR 提交说明，供 README 和 GitHub 贡献入口引用 |
| `assets/interface.json` | 开发环境的项目入口，声明控制器、资源、Agent 和任务导入顺序 |
| `assets/interface/tasks/` | 界面任务、选项及预设声明，通过 `interface.json` 的 `import` 加载 |
| `assets/i18n/` | `interface.json` 声明的翻译文件 |
| `assets/resource/{base,tw,en,jp,kr,windows}/` | MaaFramework 资源包，包含 Pipeline、图片及所需模型 |
| `assets/models/` | 公共资源中没有的 OCR 模型，附来源、许可证和转换说明；打包时由 `tools/ci/configure.py` 复制到对应资源包 |
| `assets/requirements.txt`、`assets/CONTACT` | 随发行包提供的运行依赖清单与联系方式 |
| `agent/` | Python 自定义识别与动作 |
| `tools/checks/check_resource.py` | 按参数顺序加载资源包，检查框架能否正常解析 |
| `tools/checks/check_i18n.py` | 检查界面国际化硬编码、翻译键缺失及未使用的键；运行 `python tools/checks/check_i18n.py` |
| `tools/checks/requirements.txt` | 资源检查使用的 Python 依赖 |
| `tools/i18n/convert_to_zh_hant.py` | 从简体中文全量生成界面和 Agent 日志的繁体中文翻译；依赖及运行方式见[国际化维护说明](i18n维护说明.md) |
| `tools/checks/pre-commit-config.yaml` | 图片、JSON/YAML 和 Markdown 的提交检查配置 |
| `tools/ci/install.py` | 将项目文件和 MaaFramework 运行库装入 MFAAvalonia 发行暂存目录 |
| `tools/ci/install_mxu.py` | 组装并校验 MXU Windows x64 发行目录 |
| `tools/ci/resource_layout.py`、`tools/ci/package_common.py` | MFAAvalonia 与 MXU 共用的资源路径映射、文件复制及暂存清理逻辑 |
| `tools/ci/` | 依赖准备、版本解析、发行打包及测试 |
| `tools/format/` | `.prettierrc`、npm 格式化依赖、锁文件及本地安装的 `node_modules/` |
| `deps/tools/` | 项目已有的 JSON Schema |
| `assets/MaaCommonAssets/` | 上游公共资源子模块，供打包阶段准备 OCR 模型 |
| `vendor/MaaFwApp/` | Android 客户端子模块；构建说明见[Android 构建与发布](Android构建与发布.md) |
| `docs/`、`page/` | 项目文档与展示页面 |

根目录的 `README.md`、`LICENSE` 分别提供项目说明和许可证，`AGENTS.md` 提供 AI 工具的开发指引，`.gitignore`、`.gitmodules` 分别定义 Git 忽略规则和子模块。贡献指南位于 `docs/CONTRIBUTING.md`，检查与格式化配置随对应工具放在 `tools/` 下。

各资源包采用上游约定的 `pipeline/`、`image/`、`model/` 层级。Pipeline 内按功能分组；语言与平台资源包包含各自的覆盖文件。

| Pipeline 分组 | 内容 |
| --- | --- |
| `common/` | `base.json` 和公共战斗、事件、记录选择节点 |
| `daily/` | 登录、好友、基金、邮件、委托、商店、交流、任务领奖 |
| `combat/` | 作战、猎影合围、真格挑战 |
| `activity/` | 活动及活动挑战 |
| `invite/` | 邀约 |
| `climb_tower/` | 爬塔 Pipeline |

框架递归加载 `pipeline/` 中的 JSON，同一资源包的 Pipeline 文件共享节点命名空间。图片路径相对于资源包的 `image/` 目录。

## 源码与发行布局

MFAAvalonia 与 MXU 分别通过 `tools/ci/install.py`、`tools/ci/install_mxu.py` 组装发行目录，并共用 `tools/ci/resource_layout.py` 的资源路径映射和 `tools/ci/package_common.py` 的文件复制、暂存清理逻辑。

当前 `install.yml` CI 工作流构建并发布 MFAAvalonia 版本，覆盖 Windows、Linux 和 macOS 的 x64、ARM64 平台。MXU 由 `install_mxu.py` 提供 Windows x64 打包入口，目前未接入该发行工作流。

MFAAvalonia CI 使用上游最新的非草稿发布版本，包含预发布版。MaaFramework 的 Python 绑定优先使用同版本、对应平台的 PyPI wheel；缺失时，`tools/ci/prepare_maafw.py` 使用宿主 Python 从同一标签的源码与 SDK 构建 wheel，供发行 Python 安装。

CI 将上游 MFAAvalonia 客户端解压到 `MFA/`，由 `install.py` 先在 `install/` 组装项目资源、Agent、Python 运行环境及 MaaFramework 运行库，再把客户端文件合入该目录并打包归档。`install_mxu.py` 则把预先准备的 MXU 客户端和依赖装入 `install/`，并校验发行文件。上述目录均为构建暂存目录，不是源码目录。

两个桌面打包入口会分别转换发行版的 `interface.json`，MFA 根据目标平台设置 Python 启动路径。OCR 模型由 `tools/ci/configure.py` 在发行资源目录中准备：已有完整模型时保留，缺少时从公共资源导入默认模型；韩服模型另存于 `resource/kr/model/ocr`，由 v6 small 检测模型与 `assets/models/korean_PP-OCRv5_mobile_rec` 的识别模型、字符表和许可证组成。打包器校验检测模型、识别模型及字符表。

| 源码路径 | 发行包路径 |
| --- | --- |
| `assets/interface.json` | `interface.json`，保留各客户端已有的发行转换 |
| `assets/interface/tasks/` | `interface/tasks/` |
| `assets/requirements.txt`、`assets/requirements-win-x64.txt` | `requirements.txt`；Windows x64 合并专用清单与通用依赖，其他平台使用通用清单 |
| `assets/CONTACT` | `CONTACT` |
| `assets/resource/<包>/pipeline/common/base.json` | `resource/<包>/pipeline/base.json` |
| `assets/resource/<包>/pipeline/{daily,combat,activity,invite}/<文件>.json` | `resource/<包>/pipeline/<文件>.json` |
| `assets/resource/<包>/pipeline/common/` 中其他文件 | `resource/<包>/pipeline/common/` |
| `assets/resource/<包>/pipeline/climb_tower/` | `resource/<包>/pipeline/climb_tower/` |
| `assets/resource/<包>/{image,model}/` | `resource/<包>/{image,model}/` |

`resource_layout.py` 根据路径映射，将源码中的部分 Pipeline 功能分组转换为客户端兼容的发行目录；映射表中的文件会平铺到 `pipeline/` 下，`common/` 的其他文件及 `climb_tower/` 保持原有层级。

MFAAvalonia CI 的 Windows 归档为 `MaaStellaSora-win-<架构>-<版本>.zip`，Linux 和 macOS 归档为对应的 `.tar.gz`；归档内是 `install/` 的内容。MXU 的 `install_mxu.py` 默认也将组装目录写入仓库根目录的 `install/`，并要求 `MXU/`、`deps/` 及 `install/python/`、`install/deps/` 已准备好。具体本地参数见脚本的 `--help`。

界面入口通过 `import` 加载 `interface/tasks/` 中的任务声明。开发环境的 Agent 入口为相对于 `assets/interface.json` 所在目录的 `../agent/neural_main.py`；Windows x64 发行包使用 `agent/neural_main.py` 注册神经网络爬塔与原有任务，其他平台使用 `agent/main.py` 并省略神经网络爬塔资源。

## 资源加载

官服加载 `base` 资源包；台服、国际服、日服、韩服分别在 `base` 之后加载 `tw`、`en`、`jp`、`kr`。桌面控制器通过 `attach_resource_path` 最后追加 `windows`。

资源按声明顺序叠加，后加载资源覆盖先加载资源。界面入口按 `import` 顺序导入任务和选项：任务依次追加，同名选项由后导入的定义覆盖。
