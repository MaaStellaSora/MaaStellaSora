# 爬塔（神经网络）

Windows x64 原生游戏的国服、日服可从主页启动此任务，选择属性塔和爬塔次数。首次进入核心潜能页时从背包读游戏内预设；同一任务的后续对局复用目标，各局单独记录持有和库存。原有爬塔任务不受影响。

专用 Pipeline 负责导航、点击和等待；`agent/custom/action/climb_tower_neural/` 负责识别结果、推理和记录。名称、区服文字、事件和音符规则分别在目录与 Pipeline 的配置中维护。

界面切换时，补点前的短等待到期只表示该重新看一眼画面，不触发错误截图；最终等待仍走框架的超时诊断。

- 冻结的 M213 只按潜能收益比较选卡、刷新、饮品及强化，当前不会购买音符。普通事件按可见、可执行的选项估值，答题沿用游戏答案规则。
- 商店按从开局走到该店时的状态估值：首店货架读出后即清除初始标记；终店内的返回阶段仍是路线推进（`ADVANCE`），离店后路线已走完，才记为终局（`END`）。
- 预设日志列出含核心潜能的全队目标和三人的分项。「预期」是所选动作的终局估值；候选行显示相对上次预期的变化。
- 事件菜单不显示楼层。首层追加事件之后还有二层固定事件；二层事件之后则进三层战斗。两条路线都可能时，按各自概率合并选项估值，记录中楼层留空并保留候选。事件奖励卡沿用这个判断。
- 决策所用的潜能目录和目标等级必须齐全。如果只是池内顺序未知，事件、选卡和商店都保留已观察到的位置，其余位置按预设目录顺序填入 M213。决策记录用 `evaluation_pool_order_basis` 标明估计或唯一投影；原始池位观测仍保留未知。
- 同队有同名、同品质潜能时，选卡和领取都要核对归属。普通潜能页的候选来自同一角色；强化页可能混合角色，不能用相邻卡片代认。归属仍不明确时不点击，也不更新持有。
- 事件页按金币图标定位钱包，避免把展开音符栏中的数量当余额。钱包文字检测没有给出字框时，用同帧白字轮廓定位，再由 OCR 确认金额；定位本身不产生金额。候选卡名只在同一次 OCR 内拼接分行；多次读取须一致才能确认，未确认的卡不计入已知持有。
- 已匹配答案的答题事件允许暂时读不到金币。奖励页确认的余额会成为下次判断金币增量的起点；它本身不能确认事件楼层。
- 新角色的背包标题只拼接同一次 OCR 的文字，按其中最低置信度确认。连续领取潜能时，若下一页名称暂未读全，用原卡面和「拿走」按钮一起消失、随后重新出现的卡面和按钮确认换页。重新读清原页则继续确认原次领取。
- 对局记录保存在本机。「分享数据，帮助改进模型」默认关闭。开启后，每局结算或中断时单独上传该局的结构化日志，不等整项任务结束。收尾最多等 5 秒；未收到回执的对局留在队列，后续开启分享时继续重试。接收端为 `POST https://35.213.73.34/v3/runs`，无需 Token，不含截图，用于错误分析和后续音符、潜能联合模型开发。

更新潜能目录时，用 `python tools/catalogs/tower_catalog.py expand agent/custom/action/climb_tower_neural tmp/tower-catalog` 展开维护目录，更新完成后运行 `python tools/catalogs/tower_catalog.py compact tmp/tower-catalog` 生成发行目录。发行版按潜能 ID 存储，保留中日名称及来源。
